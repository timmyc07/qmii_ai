# 本機生成計畫驗收紀錄

量測日期：2026-10-17（Asia/Taipei）。重跑方式與固定案例見 [本機生成基準](BENCHMARKS.md)。原始資料與生成媒體位於本機 `output/benchmarks/baseline/`；下載完成後的主要影片重測位於 `output/benchmarks/comparison/`，均不提交 Git。

## 環境與方法

- RTX 5070，12,227 MiB VRAM；32 GB RAM，作業系統可見約 30.88 GiB。初始 Windows／其他程序 GPU 占用約 1.6 GiB。
- ComfyUI 0.41.0、Portable Python 3.13.14、PyTorch 2.14.0+cu130、CUDA 13.0；Qwen CLI commit `d637cfb`。H3 使用 ComfyUI 原生節點，主模型為 `minimax_h3_fl2va_pruned_int8_convrot.safetensors`，編碼器為 `qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors`。
- H3 LoRA：`minimax_h3_fl2v_turbo_4step_v1.0_768p_comfyui_bf16.safetensors`、`minimax_h3_fl2v_turbo_8step_v1.0_comfyui_bf16.safetensors`；原版不載入 Turbo LoRA。影片與音訊 VAE 沿用現有 FP16／FP32 檔。
- Wan 使用固定 revision `ee6f4a40737a995bf5818954cfce6d59443b0f04` 的官方 5B FP16、UMT5 FP8、Wan 2.2 VAE，三個下載皆通過完整 SHA256。
- 保留 `--lowvram`、原生 offload 與 RAM pressure cache，使用 PyTorch attention；未安裝 SageAttention／Triton。分頁檔確認為系統管理，檢查時配置 21,636 MiB，未修改。
- 所有案例固定 seed 42、896×512；影片固定 141 幀、24 fps、5.875 秒。每條路徑一個樣本，重測僅比較主要路徑；這不是多種題材的平均速度或品質排名。Turbo4 的 768p 原生解析度、12～15 秒與高解析度容量未驗證。
- Wan 使用 20 步、CFG 5、UniPC／Simple、shift 8，負面提示詞留空。未掃描負面提示詞、步數或 720p 原生尺寸，因此結論只涵蓋此固定配方，不能視為 Wan 的最佳品質或速度上限。
- 共用 GPU 鎖涵蓋整輪基準，並以另一個真實程序驗證鎖的排他性。整機 VRAM／RAM 約每秒取樣，包含基準程序、桌面與其他應用；同引擎間保留原生快取，明確記錄命中的節點。ComfyUI 服務啟動不算在案例總時間內。
- 第一輪部分案例與模型下載重疊，保留作功能與容量紀錄；主要 H3／Wan 比較在下載完成後重跑。不得將首次磁碟載入與暖快取結果描述成同一種延遲。

本輪維持 H3 Turbo4 為既有有聲 I2V 預設；Wan 不因參數較少就被標示為更快。H3 原版 20 步與 Wan T2V 的首輪結果分別為 301.35／209.35 秒，保留於功能基準，未混作本輪同輸入的速度排名。

兩輪影片後切回 Qwen 均成功，分別約 47.37／46.67 秒；第二輪 Qwen 整機 VRAM 取樣最高 9,496 MiB、RAM 約 20.27 GiB。切換使用原生 `/free` 卸載與清除執行快取後才啟動 CLI，沒有同時執行兩個生成引擎。20 次 GPU 案例均產生可解碼輸出；不能把這個小樣本成功率外推成所有尺寸／片長的穩定性保證。

## 畫質與一致性抽查

以下為固定樣本的人工圖片／首中尾幀觀察，沒有以成功狀態推定畫質合格，也沒有自動身分相似度分數。

重測 H3 Turbo8 與 Wan I2V 的三張截圖雜湊與首輪相同；H3 Turbo4 截圖雜湊不同，目視仍是近似的轉頭與微笑。固定種子有助比較，不保證跨執行的位元完全相同；本輪沒有追查數值差異來源。

- Qwen 生圖產生符合描述的藍衣成人肖像。Qwen 修改與 SuperDuper 修改均改為綠衣，人物與姿態大致延續；Qwen 修改的皮膚／髮絲呈現較強銳化，並非只改衣服像素。
- 多圖參考成功融合成單張肖像，但背景顆粒、輪廓與皮膚銳化明顯，不能當成無損身分複製。
- SuperDuper 與 NSFW Adv 文字生圖都能產生茶杯靜物。NSFW Adv 的 0.6 重繪樣本更換了人物外觀且未改成指定綠衣，屬提示詞／身分保留品質不合格；技術生成成功不等於任務意圖達成。
- H3 4 步、8 步與原版均產生可辨識的轉頭與微笑，首中尾抽查沒有黑幀或明顯臉部崩壞。三點抽查不能排除其他影格的閃動，也不能證明跨題材身分一致性。
- 「以首幀作尾幀」的中段有轉頭／微笑，尾端回到接近原始正面與表情；證明端點引導有效於此樣本，不保證無縫循環或中段每幀鎖定。
- 「自選尾幀」的開頭保持藍衣，中段仍是藍衣轉頭／微笑，結尾回到指定綠衣正面尾幀；衣色不是整段都一致。尾幀確實傳入原生條件，但不能當作逐幀一致性保證。
- 加入主體描述的 H3 樣本仍有可辨識的轉頭與微笑；單次對照不足以宣稱比原提示詞更能保留身分，維持選配。
- Wan T2V 能產生人物微笑畫面，影像較柔和；沒有參考圖片時不與首幀人物作身分比較。Wan I2V 的首中尾保持藍衣與近似面貌，但本次只呈現輕微微笑，沒有 H3 樣本那樣明顯的轉頭，動作遵循較弱。
- H3 音軌存在並能解碼，Wan 沒有音軌。未進行主觀聽測、語音或嘴形品質評測；本輪提示詞只有安靜室內環境聲，不能外推到台詞用途。

## 量測解讀與後續選擇

Qwen 首次生圖的 CLI 日誌記錄 diffusion／文字模型載入約 14.76／13.04 秒、VAE 載入約 1.44 秒、採樣約 17.20 秒、解碼約 2.54 秒，端到端約 64.98 秒。解碼與 VAE 載入可能嵌套，不能將所有日誌計時直接相加。H3 與 Wan 記錄 loader、條件、採樣及解碼節點耗時；原生延遲載入發生在節點內，尚無獨立的純 GPU 權重搬移時間。

本輪原版 H3 整機 RAM 取樣最高約 30.84 GiB，最低可用約 44 MiB，顯示環境非常吃緊。系統管理分頁檔提供提交容量，不能據此承諾常駐、秒切或所有片長都不會 OOM。

現有 H3 保留原生影音與首尾幀用途；Wan 只作無聲 T2V／I2V 實驗路徑，不代替有聲或尾幀工作流。日常預設與介面維持既有模式。尚無已驗證的 attention／補幀／放大收益，也未觀察到本輪解碼失敗的必要修正，因此階段 4 選配維持關閉。

桌面已有配方、聲音、首尾幀、主體描述、參數保存與任務紀錄；手機表單仍以四種圖片模式為主，作品庫可播放／下載影片。此輪沒有足以要求新模式卡片、Remix、自動尾幀、導演助手或逐幀修臉的新增需求，階段 5 不擴充 UI。
