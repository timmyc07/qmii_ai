# 本機 AI 全模態生成平台優化計畫

本計畫以目前的 RTX 5070 12GB 與 32GB RAM 為基準，先量測及整理現有 Qwen、Wan 與 MiniMax H3 工作流，再依實測結果決定是否加入額外算子、後處理或新 UI。目標是在本機可承受的記憶體範圍內，提供可重現的圖片、影片與影音生成；不以多個大型模型同時常駐或「100% 身分鎖定」作為設計承諾。

## 本機基準與限制

截至 2026-10-17 的本機檢查結果：

- GPU：NVIDIA GeForce RTX 5070，12,227 MiB VRAM；檢查當下 Windows 桌面使用約 1,519 MiB。實際可供生成使用的顯存會隨桌面與其他程序變動。
- RAM：總量約 30.9 GiB；檢查當下可用約 12.5 GiB。可用量會變動，不能據此保證大型模型全部留在 RAM 或能秒速切換。
- RTX 5070 屬 Blackwell，硬體支援 FP4；能否使用特定量化權重仍取決於模型檔、PyTorch、CUDA、ComfyUI 與節點版本。
- 現有 Qwen Turbo 執行環境與 H3 ComfyUI 工作流分開。單一工作流跨兩個引擎呼叫模型，需額外處理載入、佇列與記憶體，不能假設只要串節點便可即時完成。

因此採用**單一 GPU 工作逐次執行、需要時才載入模型**作為基準。CPU offload 與系統管理的分頁檔可作為容量措施，不能視為 VRAM 或實體 RAM，也不應承諾降低載入延遲。

## 現有功能與範圍

專案目前已有 Qwen Image 2.1 Turbo 圖片工作流、H3 圖片生影片、H3 Turbo 4/8 步與原版配方、影音輸出、首幀／尾幀條件、可選主體描述，以及任務參數記錄。細節見 [模型說明](MODELS.md)、[H3 參數與身分一致性](H3.md) 與 [工作室說明](STUDIO.md)。

本計畫先驗收並補足現有能力，不重做已具備的功能。以下原始構想不列為保證或第一階段交付：

- Qwen 與 H3 在 RAM／VRAM 雙模型常駐、秒速切換。
- 由自動生成尾幀達成 100% 身分或場景鎖定。
- 未經版本相容性檢查即安裝 SageAttention，或預設每段影片都補幀、放大。
- 將 H3 的 Qwen3-VL 編碼器直接視為可供 UI 呼叫的通用導演助手。

## 執行階段

### 0. 建立可比較的基準

先記錄目前執行環境與工作流版本：Qwen Turbo、ComfyUI、PyTorch、CUDA、H3 節點、模型與 LoRA 檔名。對每個既有路徑分別執行相同規格的基準案例，記錄模型載入時間、生成時間、峰值 VRAM／RAM、輸出尺寸、片長、是否成功，以及畫質結果。

驗收條件：每種工作流至少有一組可重跑的提示詞、參數和結果紀錄；確認任務逐次執行，沒有兩個 GPU 生成同時搶用顯存。基準前不更改 pagefile 或安裝新 attention 套件。

### 1. 整理記憶體與模型切換策略

保留 ComfyUI 原生記憶體管理，檢查啟動參數的實際作用後再作小幅調整。只有量測證實需要留出顯存時才設定 `--reserve-vram`；`--cache-none` 是執行快取選項，不能當作 VRAM 設定。不要在未確認現有流程與啟動記錄前移除 `--lowvram`。

維持單一 GPU 任務佇列，模型切換以實際載入時間比較。Windows 分頁檔先維持系統管理；只有工作管理員顯示提交量不足或有明確記憶體錯誤時，才重新評估容量。不要把固定 32GB 分頁檔當作加速或防止所有閃退的措施。

驗收條件：Qwen、Wan、H3 各自可完成基準案例；切換與連續任務不發生 OOM；記錄記憶體占用和載入時間，避免用「常駐」或「秒切」描述未量測的效果。

### 2. 比較影片生成路徑

先比較既有 H3 配方，再評估新增 Wan 2.2 TI2V-5B。ComfyUI 官方說明 5B 工作流可透過原生 offload 在 8GB VRAM 執行，因此 RTX 5070 具備測試條件；仍須在本機用預定解析度與片長確認。Wan TI2V-5B 適合作為快速 T2V／I2V 測試路徑；H3 保留需要原生影音和首尾幀條件的用途，兩者功能不完全相同。

以相同片長、相近輸出尺寸及固定提示詞，比較 Wan 5B、H3 Turbo 4 步、H3 Turbo 8 步；需要時再測 H3 原版。記錄速度、動態穩定性、聲音與可用率，依結果決定簡易模式的預設路由。

驗收條件：完成一張比較表，明確記錄各路徑支援的輸入、是否產生音訊、典型生成時間、峰值記憶體與已知限制；UI 不把無聲路徑描述成有聲生成。

### 3. 使用現有 H3 首尾幀做一致性驗收

先使用現有首幀、同圖作尾幀、自選尾幀與主體描述選項，固定種子比較結果。尾幀是端點引導，不代表中間每幀都被鎖定；提示詞生成的尾幀也不構成身分保證。ComfyUI 官方工作流支援首幀／尾幀輸入，並說明模型生成兩端之間的動作。[官方 H3 工作流](https://docs.comfy.org/tutorials/video/minimax/minimax-h3-native)

驗收條件：確認現有 API、參數驗證和前端都能正確傳遞尾幀；用固定案例檢視開頭、中段、結尾。只有手動尾幀使用者需求明確且現有流程不滿足時，才規劃尾幀自動生成；先測額外的引擎切換時間與結果品質，不承諾 2 秒完成或 100% 一致。

### 4. 以量測結果決定可選加速與後處理

- **SageAttention：** 先核對 ComfyUI 所用 Python、PyTorch、CUDA 及 RTX 50 相容版本，再在獨立環境安裝／驗證。上游 SageAttention 說明 Blackwell 路徑需要 CUDA 12.8 或更新版本；實際端到端收益仍以本機基準為準。[官方 SageAttention 專案](https://github.com/thu-ml/SageAttention)
- **VAE 分塊解碼：** 只有影片長度或解析度測試顯示解碼階段 OOM，且目前 H3 節點支援相容的分塊選項時才啟用。先確認輸出接縫與解碼耗時。
- **RIFE 與放大：** 作為生成後可選處理，不預設串入每次生成。先以少量片段比較 24→48 fps 與 768p→1080p 的耗時、顯存、畫面瑕疵和檔案大小，再決定是否提供按鈕。

驗收條件：每項選配都能單獨關閉；記錄啟用前後耗時、記憶體與輸出差異。未達到可重現收益或引入明顯畫質問題就不納入預設工作流。

### 5. UI 與助手功能後置

先確認現有設定、任務參數紀錄及手機版表單的實際缺口，再新增模式卡片或 Remix 操作。若把 H3 輸入拆成畫面、音效、台詞欄位，後端仍要依模型提示詞格式組合；欄位分開不代表音訊通道獨立控制，也不保證各語言的對嘴品質。

Qwen3-VL-32B 助手需先確認可獨立呼叫的推論介面、載入方式、GPU／RAM 占用和排程方式。優先測序列執行；只有使用者在實測後仍需要生圖期間同時呼叫助手，才評估併發。臉部修復逐幀處理可能造成畫面閃動，不列為身分鎖定功能，僅在獨立影片樣本驗證後再提供選配。

驗收條件：新增 UI 前列出現有功能與差距；新增欄位要能重現到任務參數；助手不與生成任務同時搶用 GPU，除非獨立測試證明可行。

## 建議交付順序

1. 完成階段 0 基準與版本盤點。
2. 完成階段 1 記憶體策略與逐次佇列確認。
3. 完成階段 2 Wan／H3 品質和速度比較，決定模式定位。
4. 完成階段 3 現有 H3 首尾幀驗收。
5. 依 OOM、速度和使用者差距，選做階段 4、5 的項目。

每階段先檢視其驗收結果，再決定是否進入下一階段；沒有實測收益的選配不納入預設。程式或 UI 工作開始前，另依變更範圍規劃實作、測試與版本打包。
